# Security Policy

Sentinel-RAG is, in part, a security-testing tool for RAG systems (prompt
injection, retrieval poisoning, data exfiltration probes). Treat it, and any
system you point it at, accordingly.

## Reporting a vulnerability

If you find a security issue in Sentinel-RAG itself (not in a system you are
using Sentinel-RAG to test), please report it privately:

- Open a GitHub Security Advisory ("Report a vulnerability" under the
  Security tab) on this repository, or
- Email the maintainer address listed in the repository's GitHub profile.

Do not open a public issue for undisclosed vulnerabilities. We will
acknowledge reports within 5 business days.

## Supported versions

Only the latest `v1.x` release line receives security fixes during the
pre-1.0/early-1.0 phase.

## Responsible use of the adversarial toolkit

`sentinel attack` generates and runs prompt-injection, retrieval-poisoning,
and data-exfiltration test cases against a RAG system you control or are
explicitly authorized to test. Do not point it at systems you do not own or
do not have written authorization to test.

- All attack payloads shipped in `datasets/adversarial/` use **synthetic**
  secrets (clearly marked `SENTINEL-TEST-SECRET-...`) and non-destructive
  instructions. No real credentials, real exploits, or destructive payloads
  are included or generated by this project.
- Attack outcomes are classified (`SAFE` / `PARTIAL` / `FAILED` / `UNKNOWN`)
  from your own system's observed behavior — Sentinel-RAG does not send
  data anywhere external.
- See `docs/security/threat-model.md` for the full threat model, assets,
  and residual risks.

## Secrets and configuration

- Never commit `.env`; use `.env.example` as a template.
- All provider API keys (OpenAI, Anthropic) are read from environment
  variables and are optional — the deterministic local provider requires no
  credentials and is the default for tests and CI.
- CI runs `bandit` and dependency review on every PR; secret-scanning
  should be enabled at the GitHub repository settings level by the
  maintainer.
