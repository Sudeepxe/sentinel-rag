# Golden Evaluation Dataset (`v1.json`)

53 cases across 16 categories, generated by `scripts/build_golden_dataset.py` and validated against
`sentinel.schemas.dataset.EvaluationDataset`. All content is grounded in one coherent fictional SaaS
company ("Northwind Cloud") knowledge base so documents can be realistically reused/combined across
multi-document and multi-hop cases, rather than being disconnected one-off snippets.

Regenerate with: `python scripts/build_golden_dataset.py`

## Why a generator script, not hand-edited JSON

The dataset is code so it stays internally consistent (shared document fragments are defined once
and reused, ids can't drift) and is trivially regenerable/extensible. Every document and question
is real, specific prose — not lorem ipsum or templated filler — and the script's output is
validated on write.

## Categories and what each detects

| Category | n | Failure it's designed to catch |
|---|---|---|
| `direct_factual_retrieval` | 5 | Basic retrieval/citation correctness on unambiguous single-fact questions |
| `semantic_retrieval` | 5 | Retrieval that requires bridging paraphrased/reworded queries to source terminology |
| `multi_document_reasoning` | 5 | Answers requiring combining facts from 2+ documents |
| `multi_hop` | 4 | Answers requiring a chained inference (not just concatenation) across documents |
| `noisy_documents` | 3 | Relevant document buried among many topically-similar-but-irrelevant ones |
| `irrelevant_documents` | 3 | Corpus with exactly one relevant document among clearly unrelated ones |
| `conflicting_evidence` | 4 | Two documents disagree; system should prefer the authoritative/current one, not blindly merge |
| `unanswerable` | 4 | Question has no answer in the corpus; system must refuse, not hallucinate |
| `citation_verification` | 3 | Multi-part answers where each part needs distinct citation support |
| `refusal` | 3 | Mix of should-refuse and should-NOT-refuse cases to catch both false refusal and unsafe answering |
| `prompt_injection` | 1 | Standing regression check: direct injected instruction in a retrieved document |
| `indirect_prompt_injection` | 1 | Standing regression check: instruction embedded in otherwise-plausible document text |
| `stale_information` | 3 | Freshness-policy-sensitive: does the system prefer current info, and can it still answer about a stated historical value on request |
| `duplicate_information` | 3 | Near-duplicate chunks/documents; citation should still point at a sensible source |
| `long_context` | 3 | Relevant document buried among 12 filler documents, stressing retrieval-among-many |
| `ambiguous_questions` | 3 | Underspecified questions with multiple valid readings |

The two golden-dataset injection cases (`inject-001`, `inject-002`) are a *small, standing*
regression check distinct from the full systematic adversarial suite
(`sentinel attack generate`, 795 generated cases across all 15 attack classes — see
`docs/experiments/08-prompt-injection-robustness.md`). `tests/adversarial/test_attack_pipeline.py`
asserts these two never leak their embedded canary.

## Limitations and overfitting risk

- **This dataset is small (53 cases).** Aggregate metrics move by ~1.9 percentage points per
  single case flip. Treat any single-digit percentage-point difference between two configurations
  as noise unless backed by a bootstrap confidence interval (`sentinel compare`).
- **Per-case corpora are small** (median ~3 documents, up to 96 for the long-context cases). This
  means `recall@5` saturates at 1.0 for most retrieval configurations tested in
  `docs/experiments/01-06` — a real, reported ceiling effect, not a claim that those configurations
  are equivalent in general. See each experiment's Limitations section.
- **Do not hand-tune the reference pipeline against this dataset's specific wording.** Doing so
  would make every benchmark number in this repository meaningless (Goodhart's law applied to a
  benchmark the same organization both builds and is graded by). No chunk boundary, synonym list,
  or threshold in `sentinel/retrieval` or `sentinel/generation` was chosen by looking at golden-set
  failures and patching around them; where a genuine bug was found via this dataset (e.g., the
  citation-splitting off-by-one, or the missing-title chunk-text bug), the fix is a real, general
  correctness fix documented in the corresponding code/test, not a narrow patch for one case's
  wording.
- **Fictional domain.** "Northwind Cloud" policies are invented for this dataset; none of the
  numbers (pricing, SLA percentages, retention periods) reflect any real company.
- **Reference answers are short and specific by design**, to keep the mechanical
  `answer_relevance`/`faithfulness` lexical-overlap proxies meaningful; this makes the dataset
  poorly suited, as-is, for evaluating long-form or highly discursive answer styles.
